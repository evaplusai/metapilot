Build your own GitHub Copilot agent harness

A step-by-step tutorial for metapilot: the Copilot-only slim copy of ruvnet/metaharness.

1What you are building

An agent harness is a small, owned wrapper around an AI model. It gives the model a name, rules, agent personas, skills, and a set of tools it is allowed to use. Underneath, you still talk to whatever model Copilot uses. The harness adds knowledge of your project and a safety net.

metapilot keeps only what you need for GitHub Copilot in VS Code:

FolderWhat it does
packages/create-agent-harnessThe metaharness and harness command-line tools.
packages/kernel-jsThe kernel. It runs as WebAssembly (.wasm), already built and taken from npm.
packages/host-copilotWrites the files Copilot reads: .vscode/mcp.json and .github/copilot-instructions.md.
packages/horizonLong-horizon planner, also prebuilt WebAssembly.
docs/adrsThe design decisions. The Copilot design is ADR-032.
You never compile Rust here. The WebAssembly files are already inside the repo, exactly as published on npm.

2Before you start

  • Node.js 20 or newer and npm. Check with node -v.
  • VS Code 1.99 or newer with the GitHub Copilot Chat extension (needed from step 8).
  • Internet access to the npm registry.

3Build metapilot

Clone the repo, install, build and test. This also makes the metaharness and harness commands available through npx.

git clone https://github.com/evaplusai/metapilot.git
cd metapilot
npm ci
npm run build
npm test
Success looks like about 1,200 tests passing, a few skipped and 0 failed.

4Look around the CLI

npx metaharness --help

The last line should say Hosts: copilot. That is the only host in this copy.

npx metaharness --list

This shows 20 templates. Start with minimal to learn, or pick a vertical such as vertical:coding, vertical:support, vertical:devops or vertical:repo-maintainer.

5Size up a repo (optional)

Before you build a harness for an existing project, ask metaharness how well it fits. These commands only read the repo and never run its code.

npx metaharness score ../my-project
Harness fit:        67/100
Compile confidence: 90/100
Task coverage:      98/100
Tool safety:        95/100
Memory usefulness:  38/100
Est. cost per run:  $0.048
Recommended mode:   CLI + MCP  (template vertical:coding)
Constraints:        6/6 hard ✓ scaffold-ready
npx metaharness analyze ../my-project

This suggests agents and commands. It writes repo-profile.json and harness-plan.json into that folder.

npx metaharness genome ../my-project

This gives a 7-part readiness report: repo type, suggested agents, risk, MCP surface, tests and publish readiness.

6Create your harness

Pick a name and a template. --target puts the new harness next to metapilot, not inside it.

npx metaharness my-bot --host copilot --template vertical:coding \
  --description "Coding helper for my project" --target ../my-bot
Scaffolded my-bot into /…/my-bot
Files: 24
Manifest: /…/my-bot/.harness/manifest.json

What you got

FileWhy it matters
.vscode/mcp.jsonTells Copilot how to start your harness's tool server.
.github/copilot-instructions.mdRules Copilot always follows in this folder.
.harness/mcp-policy.jsonThe safety net: deny by default, no network, no shell, no file writes.
bin/cli.js, bin/mcp.jsYour CLI (init, doctor, mcp start) and tool server.
src/agents/*.tsAgent personas: architect, implementer, reviewer, test-writer.
.claude/skills, .claude/commandsSkills such as plan-change and evolve, and commands such as review-diff.
install.mdA short install guide for whoever receives the harness.

Useful extra flags: --no-darwin (skip self-improvement), --sessions (crash-safe session log), --force (overwrite), --wizard (choose interactively).

Talk to the tool server directly

You can check the tool server before opening VS Code. This sends three MCP messages over stdin:

printf '%s\n' \
 '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","clientInfo":{"name":"t","version":"1"},"capabilities":{}}}' \
 '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
 '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"harness_info","arguments":{}}}' \
 | timeout 5 node bin/cli.js mcp start

You should see three replies. The last one contains your harness name, version and description.

8Connect it to Copilot

  1. Open the my-bot folder in VS Code and click Trust when asked. VS Code ignores .vscode/mcp.json in untrusted folders.
  2. Open Copilot Chat and switch the mode to Agent.
  3. Click the tools icon. You should see the my-bot server with the harness_info tool. If it is missing, run MCP: List Servers from the command palette and start my-bot.
  4. Ask: "Use harness_info to tell me about this harness." Copilot asks for permission, calls the tool and answers with your harness details.
Copilot is now using your harness, following its rules and calling its tools.

9Run the safety checks

Go back to the metapilot folder. Each harness command takes the path of your harness.

npx harness doctor ../my-bot

Checks structure, manifest hash and kernel version. Expected: Result: HEALTHY.

npx harness mcp-scan ../my-bot

Security-scans the tool surface. A new harness shows MEDIUM with two findings (see the table below).

npx harness diag ../my-bot

Checks the kernel version. Expected: PASS kernel versions match exactly.

npx harness score ../my-bot

Gives a scorecard and grade. A new harness gets Verdict: A.

npx harness validate ../my-bot

Runs all the checks together before you publish.

Warnings you will see, and what they mean

MessageMeaning
.claude-plugin/plugin.json absentOnly matters for Claude Code plugins. Safe to ignore for Copilot.
Secrets not deniedNothing explicitly blocks reading .env files. Add that rule before you give the harness any file-read tools.
unpinned dependency range(s)^0.1.0-style versions. Pin exact versions before publishing.
FAIL secrets — no active gcloud projectA Google Cloud secret check. Expected unless you use GCP.
native unavailableNormal. This repo runs the kernel as WebAssembly.

10Make it yours

  • Behaviour: edit .github/copilot-instructions.md. This file has the biggest effect on Copilot.
  • Personas: edit the prompts in src/agents/*.ts.
  • Tools: add tools to bin/mcp.js. Keep them read-only unless you really need more.
  • Permissions: .harness/mcp-policy.json denies everything by default. Only loosen it on purpose, then run mcp-scan again.

After each change:

npm test && npm run doctor
Don't hand-edit .harness/manifest.json. To get template updates, run npx harness upgrade ../my-bot to see the drift plan, then add --apply.

11Let it improve itself (Darwin Mode)

Every harness comes with Darwin Mode. It proposes small changes to the harness config, tests each one in a sandbox and keeps only the ones that measurably help. The model stays the same. It needs no network and no API key.

npm run evolve:dry
Winner: g2_v5
Lineage: baseline → g1_v0 → g2_v5
Delta over baseline: +0.110
Artifacts: …/my-bot/.metaharness

When the dry run looks sensible, run the real sandbox (3 generations, 4 children each):

npm run evolve

Read the results in .metaharness/ before you keep a change. Design notes: docs/adrs/ADR-070 to ADR-076.

12Use the local packages instead of npm (optional)

By default your harness downloads @metaharness/kernel and @metaharness/host-copilot from npm. To use the code in metapilot instead, run npm run build in metapilot, then change my-bot/package.json:

"dependencies": {
  "@metaharness/kernel": "file:/ABS/PATH/metapilot/packages/kernel-js",
  "@metaharness/host-copilot": "file:/ABS/PATH/metapilot/packages/host-copilot"
},
"overrides": { "@metaharness/kernel": "file:/ABS/PATH/metapilot/packages/kernel-js" }

Then run npm install and npm run doctor again. It should still say wasm backend.

13Use it from ruflo

metapilot is also set up with ruflo. Its MCP server has tools that call the same metaharness commands and return structured data:

ruflo toolDoes the same as
metaharness_scorenpx metaharness score
metaharness_genomenpx metaharness genome. On metapilot itself it says ready, with risk 0.275 and a local default-deny MCP surface.
metaharness_mcp_scannpx harness mcp-scan
metaharness_evolveDarwin Mode. It only proposes; you decide what to keep.

In Claude Code, ask for example: "Use ruflo metaharness_score on ../my-bot".

14Troubleshooting

ProblemFix
Copilot doesn't list the toolsTrust the folder, switch to Agent mode, run MCP: List Servers and start my-bot. VS Code must be 1.99 or newer.
npm run doctor fails at "kernel loads"Run npm install again in the harness. With local packages (step 12), run npm run build in metapilot first.
manifest hash mismatchA file covered by the manifest was edited by hand. Use npx harness upgrade <path> --apply, or scaffold again with --force.
harness sign asks for WITNESS_SIGNING_KEYOnly needed for signed releases. Set a 64-hex-character key that you keep secret.
Need help from maintainersRun npx harness diag ../my-bot --bundle > bundle.json and attach the file. Secrets are removed from it.

Known limits of this slim copy

  • Only the Copilot host is included.
  • metaharness learn is not available.
  • The WebAssembly kernel reports version 0.1.0, while the package is 0.1.8. This comes from upstream and is harmless.
  • Darwin Mode (@metaharness/darwin) still comes from npm.
